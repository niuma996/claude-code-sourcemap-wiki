# MCP Client

## Overview

The MCP Client ([client.ts](/restored-src/src/services/mcp/client.ts)) implements a complete Model Context Protocol client, supporting six transport types to connect to MCP servers. This module is the foundation of Claude Code's extensibility, enabling the AI to call external tools and access external resources.

## Transport Type Support

| Transport | Protocol | Use Case | Auth Support |
|-----------|----------|----------|-------------|
| `stdio` | Standard I/O | Local MCP server processes | None |
| `sse` | Server-Sent Events | Remote MCP servers | OAuth Bearer |
| `sse-ide` | SSE (IDE integration) | IDE MCP servers | None |
| `http` | Streamable HTTP | General HTTP servers | Custom Header |
| `ws` | WebSocket | Real-time bidirectional | Token parameter |
| `claudeai-proxy` | Claude.ai proxy | claude.ai hosted MCP | OAuth Bearer |
| `sdk` | MCP SDK | SDK-managed servers | SDK built-in |

## Core API

### `connectToServer`

```typescript
export const connectToServer = memoize(
  async (
    name: string,
    serverRef: ScopedMcpServerConfig,
    serverStats?: { totalServers, stdioCount, sseCount, ... }
  ): Promise<MCPServerConnection>
)
```

Connects to an MCP server and returns the connection state. Automatically selects transport based on `serverRef.type`:

```typescript
// stdio: local process
if (serverRef.type === 'stdio' || !serverRef.type) {
  transport = new StdioClientTransport({ command, args, env })
}

// SSE: remote server (OAuth auth)
if (serverRef.type === 'sse') {
  transport = new SSEClientTransport(new URL(serverRef.url), {
    authProvider: new ClaudeAuthProvider(name, serverRef),
    fetch: wrapFetchWithTimeout(...),
  })
}

// HTTP: Streamable HTTP
if (serverRef.type === 'http') {
  transport = new StreamableHTTPClientTransport(new URL(serverRef.url), {
    auth: async () => ({ Authorization: `Bearer ${token}` }),
  })
}

// WebSocket: bidirectional
if (serverRef.type === 'ws') {
  transport = new WebSocketTransport(serverRef.url, { token })
}
```

## OAuth Authentication Handling

### ClaudeAuthProvider

SSE transport uses `ClaudeAuthProvider` for OAuth authentication:

```typescript
class ClaudeAuthProvider {
  async tokens(): Promise<OAuthTokens | null>
  async auth(): Promise<string | null>  // Returns Authorization header value
  refreshToken(): Promise<void>         // Refresh expired token
}
```

## Request Timeout Handling

```typescript
const MCP_REQUEST_TIMEOUT_MS = 60_000  // 60 seconds

// Using setTimeout instead of AbortSignal.timeout() for timely cleanup
const timer = setTimeout(
  c => c.abort(new DOMException('The operation timed out.', 'TimeoutError')),
  MCP_REQUEST_TIMEOUT_MS,
  controller,
)
timer.unref?.()  // Allow natural process exit
```

**Why setTimeout instead of AbortSignal.timeout()?** AbortSignal.timeout()'s internal timer is lazily released in Bun (~2.4KB native memory/request × 60s). Using setTimeout allows immediate cleanup on completion.

## Batch Connection Optimization

```typescript
export function getMcpServerConnectionBatchSize(): number {
  return parseInt(process.env.MCP_SERVER_CONNECTION_BATCH_SIZE || '', 10) || 3
}

function getRemoteMcpServerConnectionBatchSize(): number {
  return parseInt(process.env.MCP_REMOTE_SERVER_CONNECTION_BATCH_SIZE || '', 10) || 20
}
```

Local MCP servers connect serially (batch size 3); remote servers connect in parallel (batch size 20).
